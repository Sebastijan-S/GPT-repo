### Compact consistency specification

These are implementation targets for a small CSS/content pass, not a new visual system. Keep existing variables `--bg #F7F5FF`, `--ink #1A1814`, `--accent #6246EA`, the lighter violet accents, current logo and images. Do not add fonts or change the industry's breadth.

| Element | Specification and visual check |
| --- | --- |
| Type | DM Serif Display for `h1/h2` and Inter for body/UI as now. Mobile `h1` 40–44px/1.05; desktop `h1` 72–88px/1.05 (existing clamp range). `h2` 32–48px/1.15. Body 16–17px/1.6; muted supporting copy at least 14px/1.5. Cap general reading lines about 60–70ch; hero bio about 38–42ch; dialog body 55–65ch desktop. Inspect EN/SR at 320, 390, 768 and 1440 plus 200% zoom. |
| Spacing | Use an 8px rhythm: 8, 16, 24, 32, 48, 64, 96px. Section inline padding about 5vw with a 20px mobile floor; sections 64–96px vertical on desktop, 48–64px mobile. Avoid reducing the current spacious character. Heading→lead 16–24px; intro→action 24–32px; card grid gap 24px. Compare consecutive section starts for a deliberate rhythm, especially Work→About→FAQ→Contact. |
| Buttons and links | One filled primary per decision point. Primary label names the 10-minute call; secondary “View work” remains an outline. At least 44px height and 16px between adjacent mobile actions. Allow long Serbian CTA wrapping without a fixed-height box. On hover, a small color change/≤2px lift only; visible text must retain contrast. Focus remains a 3px outline/3px offset; never remove it for styling. |
| Cards and images | Keep 20px radius and 16:10 reserved image boxes. `object-fit: cover` only where the important UI/brand content remains visible; inspect each image at 320, 390, 768 and 1440 and tune `object-position` per image if needed. Do not crop off app names or key interface actions. Keep status label above title; align card bottoms/buttons within each row where lengths differ. |
| Dialogs | At desktop, max width about 1000–1200px with 40–56px inner padding. At mobile, 12–16px viewport inset, 24–32px inner padding, max height around 90dvh and internal scroll. Keep 48px close target, short subtitle, then image and concise details. Close and call actions must remain reachable and keyboard-visible. |

## Ordered implementation checklist — static journey first

The list is a **release sequence**, not a request to edit source during this review. Phase 2 already has much of steps 1–3 locally; inspect its exact diff and preserve its measured functionality.

1. **Release-readiness review, day 1:** approve the Phase 2 EN/SR copy and proof labels; confirm contact inbox responsibility and privacy-policy inputs. Preserve the existing logo/color system and pre-existing CSS edit. Check local `git diff`, include the new compact logo asset, and keep the rollback commit. Visual check: [Phase 2 hero](03-implementation/en-1440-hero.png) and local EN/SR 320/390/1440 previews match approved words and identities. Functional check: email-arranged call route works without a mail app; no form is enabled.
2. **Proof and dialog pass, day 1–2:** check every card and modal image at 320/390/768/1440, set crop positions only if UI or wordmarks are cut, and keep the dialog's representative screen early. Visual check: card/dialog pair visibly names the same project; no important imagery cropped. Functional check: EN/SR inventory, demo labels, Escape, focus trap/restore and dialog-to-contact path pass.
3. **CTA and responsive clearance, day 2:** test sticky CTA against card text, contact action and footer. Adjust visibility/spacing only where overlap is reproduced. Visual check: no obscured line/control at 320/390/768 and 200% zoom. Functional check: anchors land below fixed header and above sticky bar; CTA has one clear destination and no booking-completed claim.
4. **Type, contrast and state pass, day 2–3:** measure actual line breaks in both languages; compare section spacing, read muted text on pale and black sections, inspect keyboard focus and pointer hover on an actual device/browser. Use values in the specification only where a defect survives Phase 2. Visual check: no orphaned one-word heading lines, clipped labels or low-contrast supporting text. Functional check: tab order, menu, FAQ and dialog remain intact.
5. **Phase 2 technical gates, day 3–5:** verify deployed canonical/hreflang/sitemap/HTTPS, no-JS visible content, focus restoration, local image sizes and font path, console/network clean except documented favicon gap. Repeat matched mobile/desktop Lighthouse runs and record medians plus variance, with particular attention to mobile LCP; do not call lab values field results. Test real email delivery only in a separately authorized controlled test. Inspect production on a real phone and a non-Chromium browser before declaring complete.

## Optional animation backlog — implement last

The live CSS already has a 220ms hero fade, 200ms hover/modal/sticky transitions, scroll reveals and a 10s placeholder shimmer. Phase 2 makes essential content visible by default and guards optional reveal behavior. Preserve that protection. No library, scroll hijacking, autoplay sequence or content that waits for an animation to appear. Motion should never delay a call action.

| Order / effect | Purpose and element | Trigger, duration, easing | Mobile and reduced motion | Risk and verification |
| --- | --- | --- | --- | --- |
| A1 — essential feedback only | Help users recognize interactive buttons, card details and menu controls. | `:hover`/`:focus-visible`; color/border 120–180ms `ease-out`; optional `translateY(-1px)` no more than 160ms. Focus outline appears immediately. | Keep color/focus, omit lift on touch; all transitions disabled under `prefers-reduced-motion`. | Low. Inspect hover, keyboard focus, touch pressed state and contrast on ivory, black and violet; no layout shift or button-label jump. |
| A2 — essential state only | Make menu/dialog open/close understandable without slowing access. | On explicit open/close: opacity and ≤8px transform, 160–220ms `ease-out`; controls usable/focusable as soon as opened. | Same or shorter on mobile; reduced motion uses instant state. | Low–medium due fixed overlays/blur. Verify Escape/backdrop/close, focus trap/restore, 320px/200% zoom, no body-scroll leak, and no pointer interception after close. Avoid costly backdrop blur if traces show jank. |
| A3 — optional, defer if mobile LCP remains high | Give portfolio cards slight tactile affordance. | Pointer hover only: ≤2px `translateY`, subtle shadow 150–180ms `ease-out`. | No hover transform on coarse pointer; instant/static reduced-motion state. | Low–medium if many large shadows repaint. Profile scrolling/hover on midrange mobile, check CLS 0 and card buttons still easy to activate. |
| A4 — optional, likely defer | Add mild section entrance rhythm without hiding proof. | First intersection: opacity from ≥0.96 and ≤6px translate, ≤250ms `ease-out`; default DOM/style remains visible and no stagger. | Disable on mobile if trace shows work; reduced motion fully static. | Medium: observers, paint and LCP. Block JS and `IntersectionObserver`, test slow network and browser back; all headings/cards/FAQ must remain visible. Do not run on hero, contact, sticky CTA or dialogs. |

**Post-motion regression gate:** rerun EN/SR 320/390/768/1440 screenshots, 200% zoom, keyboard menu/dialog/FAQ/focus, direct `#contact` navigation, no-JS/script-blocked and reduced-motion cases. Confirm no hidden essential content, no sticky overlap, no delayed or intercepted email action, no horizontal overflow, and no new console failures. Run matched mobile/desktop performance profiles; if LCP, TBT/long tasks or scroll responsiveness materially regress versus the post-static baseline, remove the optional effect. Record screenshot pairs and median lab numbers, not a claimed conversion gain.

No consequential design question blocks this review. The approved call route for this release is the Phase 2 email-arranged journey; a direct scheduler and any new testimonial/client proof remain separate future decisions.
